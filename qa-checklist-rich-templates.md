# QA Checklist: Rich Email Templates

Manual verification steps for the MJML-powered rich email templating system.

## 1. Prerequisites & Setup
- [ ] **Action:** Run `docker ps` → **Expected:** `backend` and `worker` services are running.
- [ ] **Action:** Verify branding in `app/config.py` (e.g., `SITE_NAME`, `BRAND_PRIMARY_COLOR`) → **Expected:** Constants are present and reflect desired branding.
- [ ] **Action:** Log in as an admin at `/admin/login`.

## 2. Backend API Checks

### Template Preview API
- [ ] **Action:** GET `/api/admin/templates/preview/newsletter` (in browser while logged in) → **Expected:** Returns a fully rendered HTML newsletter with mock article content and professional styling.
- [ ] **Action:** GET `/api/admin/templates/preview/confirmation` → **Expected:** Returns a rendered confirmation email with a "Confirm Subscription" button.
- [ ] **Action:** GET `/api/admin/templates/preview/nonexistent` → **Expected:** Returns `404 Not Found`.
- [ ] **Action:** Attempt to access a preview URL without an admin token → **Expected:** Returns `401 Unauthorized`.

### Rendering Correctness
- [ ] **Action:** Inspect the source of the rendered preview → **Expected:** Contains standard email-compatible HTML (tables, inline styles) generated by MJML, not raw MJML tags.
- [ ] **Action:** Check branding in the preview → **Expected:** Header logo/text color matches `BRAND_PRIMARY_COLOR` and footer contains current year.

## 3. Integration Checks

### Subscriber Confirmation Flow
- [ ] **Action:** Sign up a new subscriber on the public homepage → **Expected:** Worker logs show `send_confirmation_email_task`.
- [ ] **Action:** Check the received email (if using verified recipient) or inspect worker logs for the rendered HTML → **Expected:** Email uses the rich MJML layout instead of plain text/simple HTML.

### Newsletter Blast Flow
- [ ] **Action:** Publish a new article with "Send Newsletter" enabled → **Expected:** Worker logs show `send_single_email_task` processing.
- [ ] **Action:** Inspect the rendered newsletter content → **Expected:** TipTap content (bold, links, lists) is correctly rendered inside the responsive MJML section.
- [ ] **Action:** Verify the footer in the received/logged email → **Expected:** Contains a working "Unsubscribe" link with the correct subscriber token.

## 4. Edge Cases & Error Handling
- [ ] **Action:** Temporarily rename a template file (e.g., `base.mjml` to `base.mjml.bak`) and trigger a preview → **Expected:** Returns `500 Internal Server Error` with a descriptive error message from the renderer.
- [ ] **Action:** View the preview on a mobile device or resize the browser window → **Expected:** The layout is responsive and adjusts correctly (one-column layout on small screens).
- [ ] **Action:** Verify HTML safety in newsletter content → **Expected:** Jinja2 `|safe` filter is used, allowing TipTap's HTML to render correctly without being escaped as text.
